Step 1

File naming convention

Every post lives in the _posts/ folder. The filename must follow this exact format or Jekyll will ignore it:

Required filename format
YYYY-MM-DD-your-post-title.md

# Good examples:
2026-04-25-weekend-drive-up-north.md
2026-05-10-first-road-trip-in-the-mach-e.md
2026-06-01-summer-charging-update.md
💡 Date in filename Use the actual date you're writing the post. Jekyll uses this for sorting — newest posts appear first everywhere on the site.
⚠️ Lowercase, hyphens only Use only lowercase letters, numbers, and hyphens in the filename. No spaces, no underscores, no special characters.
Step 2

Front matter anatomy

Every post must start with a front matter block — three dashes, your metadata, three more dashes. Jekyll reads this before anything else.

  _posts/2026-04-25-weekend-drive-up-north.md
---
Opens the front matter block
layout: posts
Required. Always use posts — this applies your site's post template.
title: "Weekend Drive Up North"
Required. Shown as the post headline everywhere. Keep quotes around it.
date: 2026-04-25 09:00:00 -0500
Required. Use Eastern time offset -0500 (winter) or -0400 (summer/DST).
images: - /assets/images/photo1.jpg - /assets/images/photo2.jpg
Optional. List photos to include. Each starts with - (two spaces, dash, space). Leave blank or omit entirely if no photos.
---
Closes the front matter block. Your post content starts immediately after.
Complete example — copy and edit this
---
layout: posts
title: "Weekend Drive Up North"
date: 2026-04-25 09:00:00 -0500
images:
  - /assets/images/drive-sunrise.jpg
  - /assets/images/charging-stop.jpg
  - /assets/images/destination.jpg
---

Your post content starts here. This first paragraph
becomes the excerpt shown on the Timeline and Blog pages.

1

Resize before uploading

Your repo is public on GitHub — don't store huge files there. Target 1200px wide at 85% JPEG quality. That's sharp on any screen and stays under 300–400KB per image.

  • Mac: Open in Preview → Tools → Adjust Size → set width to 1200px. Then File → Export → adjust quality slider.
  • Free online: squoosh.app — drag in your photo, set width and quality, download.
2

Name your files clearly

Use lowercase, hyphens, no spaces. Good names make the gallery easier to manage as it grows.

# Good
2026-04-25-sunrise-at-the-lake.jpg
charging-stop-interstate-75.jpg

# Avoid
IMG_4521.JPG   ← hard to find later
my photo (1).jpg  ← spaces break things
3

Put images in assets/images/

Drag them into assets/images/ in VS Code's Explorer panel, or use GitHub's web interface to upload directly to that folder.

4

Reference them in your post's front matter

The order you list them is the order they appear. You can include as many as you want — the Timeline preview caps at 4, the post itself shows them all.

images:
  - /assets/images/sunrise-at-the-lake.jpg
  - /assets/images/charging-stop.jpg
  - /assets/images/destination-arrived.jpg

Photos listed in a post automatically appear in:

🏠
Timeline
Up to 4 thumbnail previews below the excerpt on the home page
📄
The Post
Full-width, stacked below your text — all clickable with the lightbox
🖼️
Gallery
Auto-collected from all posts — shows post title on hover, links back to post in lightbox
💡 No photos? That's fine If a post has no images, just leave the images: line out of the front matter entirely. Nothing will break.
Step 4

Writing content & Markdown

Your post content goes below the closing --- of your front matter. You write in plain text with optional Markdown formatting. No HTML needed.

✓ The excerpt rule Whatever you write in the first paragraph (before the first blank line) becomes the excerpt shown on the Timeline and Blog pages. Keep it punchy — one to three sentences that make someone want to read the rest.

Step 5

Uploading & publishing

1

Pull first — always

Before touching anything in VS Code, pull from GitHub to make sure you have the latest. CloudCannon may have committed new charging sessions since your last edit.

# In VS Code terminal or GitHub Desktop
git pull
2

Add your files

  • Copy your resized photos into assets/images/
  • Create your .md post file in _posts/
3

Commit and push

# Stage everything new
git add .

# Write a clear commit message
git commit -m "Add post: Weekend Drive Up North"

# Push to GitHub — triggers a site rebuild
git push

Or do the same thing in GitHub Desktop: stage all changed files → write message → Commit → Push.

4

Wait ~2 minutes and check the live site

GitHub Actions rebuilds the site automatically. Your new post should appear at the top of the Timeline and Blog pages, and all photos will show up in the Gallery.

⚠️ Draft posts If you want to write a post but not publish it yet, put it in the _drafts/ folder instead of _posts/. It won't appear on the live site until you move it to _posts/.
💡 Checking the build Go to your repo on GitHub → Actions tab → you'll see the build running. A green checkmark means the site rebuilt successfully. Red means something broke — click in to see the error.
Quick Reference

Pre-publish checklist

Before you commit

📁File is in _posts/ (not _drafts/)
📅Filename is YYYY-MM-DD-title.md
⚙️Front matter has layout: posts, title:, and date:
✍️First paragraph is the excerpt you want shown on Timeline
🖼️Photos resized to ~1200px before adding to repo
📸Photo paths in images: match actual filenames in assets/images/
⬇️Pulled from GitHub before starting any edits

Common mistakes

❌Spaces in the filename — use hyphens only
❌Missing the closing --- on the front matter block
❌Photo path typo — paths are case-sensitive on GitHub
❌Uploading original full-size photos — always resize first
❌Forgetting to git pull before editing — causes merge conflicts
❌Using wrong timezone offset — use -0500 Nov–Mar, -0400 Mar–Nov
